# AGENTS.md: правила для работы над CheckStock

Тестовое задание: веб-прототип складского учёта (Python, FastAPI, PostgreSQL). Автор проекта должен уметь объяснить каждое решение своими словами, поэтому важны простота и ясность кода.

## С чего начать

1. Прочитай `ARCHITECTURE.md` (вся логика и контракты API), затем `STAGES.md` (что сделано и что осталось).
2. Прочитай существующий код в `app/`: он уже соответствует этапам 0–3. Не переписывай то, что работает.
3. Найди первый невыполненный этап в `STAGES.md` и делай **только его**.

## Порядок работы на каждом этапе

1. Реализуй этап по описанию.
2. Запусти: `docker compose up -d --build`, затем проверь «Готово когда» (через `curl` или Swagger на `http://localhost:8000/docs`).
3. Покажи пользователю результат проверки и остановись. К следующему этапу не переходи без его подтверждения.
4. После подтверждения: коммит `Этап N: <название>`.
5. В конце ответа дай 2–3 строки «что сказать в видео и положить в README» по этому этапу.

## Стек и ограничения (не менять)

- Python 3.12, FastAPI, **psycopg 3 с чистым SQL**, PostgreSQL 16. **Без ORM**, без Alembic, без фронтенд-фреймворков и внешних CDN.
- Приложение запускается только через `docker compose up --build` без ручных шагов.
- Новые зависимости добавлять в `requirements.txt` только при необходимости, версии фиксировать.

## Правила учёта (нарушать нельзя)

- Остаток **никогда не хранится числом**. Он считается по журналу `movements`.
- В `movements` только `INSERT`. Никаких `UPDATE` и `DELETE`. Ошибка исправляется новой операцией.
- Каждая единица товара всегда в ровно одном месте (включая виртуальные: в пути, у маркетплейса).
- Переход статуса возможен только из одного предыдущего статуса; проверяется под `SELECT ... FOR UPDATE` строки операции. Повтор выполненного перехода возвращает 200 с `replayed: true` и **не создаёт движений**.
- Проверка «доступно ≥ qty» только под `lock_product`. Порядок блокировок: сначала строка операции, потом строка товара.
- Нехватка на ФФ: 409 с подсказкой, где есть товар. Молча брать с другого ФФ запрещено.
- ФФ не удаляется физически, только архивируется. Входящие операции на архивный ФФ запрещены, исходящие разрешены.
- После **любой** операции должен выполняться инвариант (`ARCHITECTURE.md`, раздел 11).

## Стиль

- Код короткий, без лишних абстракций. Комментарии на русском, только «почему», не «что».
- Тексты ошибок и сообщений на русском, понятные менеджеру.
- Один файл, одна ответственность: роутеры по темам (`transfers.py`, `fbs.py`, ...), общая логика расчёта в `stock.py`.
- Один запрос = одна транзакция (`with connect() as conn:`).

## Чего не делать

- Не добавлять шаблонный код, неиспользуемые файлы и функции, «на будущее».
- Не менять контракты API, описанные в `ARCHITECTURE.md`, без согласования с пользователем.
- Не трогать `docker-compose.yml` и `Dockerfile` без необходимости (кроме `COPY tests tests` на этапе 8).
- Не коммитить `.venv/`, `.idea/`, `__pycache__/`, секреты.
- Не переходить к следующему этапу без подтверждения.
